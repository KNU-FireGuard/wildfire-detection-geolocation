# Ray Casting 및 DEM 기반 산불 위치 추정 설계 (Track 1)

이 문서는 PTZ 데이터를 활용하여 2D 영상의 발화점을 3D 공간상의 광선(Ray)으로 변환하고, DEM(수치표고모델) 지형과 교차하는 좌표를 찾는 Track 1의 베이스라인 아키텍처입니다. 애자일(Agile) 원칙에 따라 복잡한 곡률이나 투영 변환을 배제하고 직교 좌표계(Flat Earth) 기준으로 직관적으로 설계되었습니다.

## 1. API Interface 규격 (필수 메타데이터 JSON)

Track 1 로직을 풀기 위해 프론트엔드/백엔드로부터 넘겨받아야 할 필수 물리 메타데이터입니다.

```json
{
  "camera": {
    "lat": 35.8562,       // 카메라 위도 (Y축 기준점)
    "lon": 128.6143,      // 카메라 경도 (X축 기준점)
    "altitude": 150.0,    // 카메라 해발 고도 (미터, Z축 기준점)
    "fov_h": 60.0,        // 수평 시야각 (Degree)
    "fov_v": 33.75,       // 수직 시야각 (Degree)
    "resolution_w": 1920, // 이미지 해상도 너비
    "resolution_h": 1080  // 이미지 해상도 높이
  },
  "ptz": {
    "pan": 45.0,          // 현재 카메라의 Pan 각도 (정북 0도 기준, Degree)
    "tilt": -5.0          // 현재 카메라의 Tilt 각도 (수평 0도 기준, 아래로 향하면 음수, Degree)
  }
}
```

## 2. 2D 픽셀 → 3D Ray 변환 (정식 핀홀 회전 모델)

- 구현: `ai/camera_model.py`, 추정기·영점 보정·360° 역산·합성 생성기가 모두 같은 모델 사용 (#55)
- 좌표계: 카메라 위치 기준 ENU (X 동, Y 북, Z 위)
- 초점 거리(px): `f = (W / 2) / tan(fov_h / 2)`, 주점은 화면 중심 `(W / 2, H / 2)`
- 카메라 축 (pan `p`: 진북 기준 시계 방향 방위, tilt `t`: 위쪽 양수, roll `r`)
  - 앞 `F = (sin p cos t, cos p cos t, sin t)`
  - 기본 오른쪽 `R0 = (cos p, -sin p, 0)`, 기본 위쪽 `U0 = R0 × F`
  - Roll 적용: `R = R0 cos r + U0 sin r`, `U = -R0 sin r + U0 cos r`
  - Roll 양수면 화면 오른쪽 수평선이 아래로 내려감
- 픽셀 `(x, y)` → 광선: `d = normalize(F + ((x - W/2) / f) R + ((H/2 - y) / f) U)`
- 방향 → 픽셀: `x = W/2 + f (d·R) / (d·F)`, `y = H/2 - f (d·U) / (d·F)`, `d·F > 0`일 때만 화면 앞쪽
- 이전 근사식과의 차이
  - 이전: 고도각 `t + atan((H/2 - y) / f)`로 가로 위치를 무시, Roll은 기울이기로 근사
  - 화면 가장자리(가로 30°)에서 고도각 약 1.3° 차이, 기울어진 카메라에서 방위 약 0.6° 차이
  - 이전 테스트는 합성 데이터도 같은 근사를 써서 오차가 상쇄돼 발견되지 않았음

## 3. DEM 교차 탐색 알고리즘 구조 (Ray Marching + Binary Search)

연산 효율을 극대화하기 위해 '일정 간격 전진(Ray Marching)'과 '이진 탐색(Binary Search)'을 결합한 하이브리드 탐색 구조를 제안합니다.

1. **초기 설정**: 
   - `ray_origin = (0, 0, camera_altitude)` (카메라 위치를 원점(0,0)으로 가정)
   - `step_size = 50.0` (미터 단위)
2. **Ray Marching (성큼성큼 걷기)**:
   - Ray 벡터를 따라 `step_size` 만큼씩 빠르게 이동하며, 해당 (X, Y) 지점의 DEM 고도 데이터를 조회합니다.
   - `광선의 Z 높이 < DEM 고도`가 되는 순간 지형과 충돌한 것으로 판단하고 반복을 멈춥니다. (이전 step과 현재 step 사이에 교차점이 존재함)
3. **Binary Search (정밀 탐색)**:
   - 충돌이 발생한 구간(마지막 `step`과 그 이전 `step` 사이의 50m 구간)을 절반씩 쪼개며(이분할) 좁혀 나갑니다.
   - 지정된 오차 범위(예: 1m 이내)에 도달할 때까지 반복하여 교차점의 정확한 최종 (X, Y, Z) 좌표를 도출합니다.

- 의미: 추정 위치를 중심으로, 카메라 자세가 σ만큼 틀렸을 때 교차점이 움직일 수 있는 범위를 모두 담는 원의 반지름
- 자세 오차가 원인이므로 각도를 틀어 광선 추적을 다시 하는 방식, 식 ΔD ≈ D·Δe/sin β의 매끈한 지형 가정 대신 실제 DEM으로 계산
  - 능선을 스치는 광선은 각도가 조금만 바뀌어도 교차점이 앞뒤로 크게 바뀜, 식으로는 표현 못 하고 다시 쏘면 드러남

### 계산 (탐지마다, 광선 추적 2회 추가)

| 항 | 계산 | 의미 |
| :--- | :--- | :--- |
| 앞뒤 | 고도각 e+σ, e−σ로 다시 교차한 거리와 원래 거리 D의 차 | 위아래 자세 오차가 거리 오차로 바뀐 크기 |
| 좌우 | D·tanσ | 방위 오차로 옆으로 빗나간 크기 |
| 화각 | 화각을 모를 때 54°·66° 자세로 구한 교차점까지 거리 | 화각 오차로 생긴 위치 차 |

- 반경 = 위 항의 최댓값, 10m 단위 올림
- 다시 쏜 광선이 하늘로 빠지면 DEM 끝(5km)까지, 근거리 하한(200m) 앞에서 막히면 200m까지를 범위로 봄
  - 하늘로 빠짐 = 연기 바닥이 능선 바로 아래라 능선 너머 어디든 가능

### 표시 기준 (FE)

- `null` → 작은 중심점 + "오차 범위 미산출", 임의 반경의 원을 만들지 않음
- 0~200m → "위치 신뢰도 높음", 실제 미터 반경의 빨간 실선 원
- 200m 초과~1km 미만 → "위치 신뢰도 중간", 실제 미터 반경의 빨간 실선 원
- 1km 이상 → "위치 신뢰도 낮음", 반경 500m로 고정한 주황색 점선 참고 원과 중심점
- 실선 원 내부는 빨간색 불투명도 8%, 참고 원 내부는 주황색 3%, 테두리는 불투명도 100%·두께 2px
- 점선 참고 원은 실제 오차 범위와 구분되는 표시용 반경, 기본·상세 정보와 중심점 안내에는 원래 오차 반경과 표시 등급 유지
- 500m는 지리적 반경으로 줌에 따라 화면 크기가 달라짐, 500px 고정 마커와 구분
- 높음·중간·낮음은 오차 반경에 따른 화면 표시 등급이며 실측 정확도나 확률을 보장하는 검증 등급은 아님
- 값은 `null`로 바꾸지 않고 그대로 저장: 계산 못 함과 매우 불확실함을 구분
