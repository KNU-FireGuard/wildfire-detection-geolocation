## 카메라별 Test 목표 흐름

```mermaid
flowchart LR
    F[Vue: CCTV별 Test] --> B[Express: 실행 관리]
    B --> A[Python: YOLO 분석]
    A -->|확정 JPEG 캡처 POST| B
    A -->|탐지 JSON POST| B
    B -->|원본 영상·캡처 조회| F
    B --> DB[(PostgreSQL: 이벤트)]
    B -->|fire 탐지 시 문자| S[SMS 제공자 · 솔라피]
```

- `source_type=test` 카메라마다 등록된 영상 하나를 분석
- Backend가 Python에 원본 파일 경로와 실행 ID를 전달
- AI가 바운딩박스 프레임과 탐지 JSON을 각각 Backend API로 전송
- Test 영상은 원본 영상 시각 기준 초당 5프레임을 선택해 YOLO 분석, 고정 6프레임 간격 분석 대체
- 불 confidence 0.3 이상·연기 0.5 이상을 클래스별로 판정, 같은 클래스이며 직전 박스와 IoU 0.2 이상인 영역을 일대일 연결
- 최근 20개 분석 프레임(약 4초)이 채워지고 같은 영역에서 16회 이상 탐지된 경우에만 탐지 JSON·위치 추정 전송, 이후 조건을 유지하는 현재 탐지로 이벤트 갱신
- 한 영역은 프레임당 한 표로 집계, 탐지 없는 프레임도 분모에 포함, 박스 영상은 확정 전 후보도 표시
- 분석 시각 간격이 0.4초 초과·역행하면 판정 초기화, 중복 프레임으로 20개를 채우지 않으며 5fps 미만·FPS 불명인 원본 영상은 실행 오류
- 32×18 회색 영상의 평균 절대 차이가 255의 25% 초과이거나 해상도가 바뀌면 판정 초기화, 기존 고정 자세의 재사용을 막기 위해 해당 실행의 위치 추정은 이후 null
- 장면 차이 비교는 큰 전환 감지용이며 점진적인 PTZ 이동의 완전한 감지는 미구현, 위 판정은 현재 Test 실행 경로에 적용
- Backend가 탐지 이벤트·확정 캡처를 저장하고 원본 영상 재생을 제공, MJPEG는 이전 작업자 호환용으로 유지
- 알림 중이 아닌 카메라에 `fire` 이벤트가 새로 생기면 해당 카메라에 설정된 번호로 문자 발송, `smoke`는 화면 표시만
- 발송 결과는 `sms_logs`에 기록, 발송 실패가 탐지 저장을 막지 않음
- 카메라별 번호 설정과 발송 내역은 문자 알림 관리 화면에서 관리
- 결과 영상 파일은 저장하지 않음

## 영상 입력

- `test` 카메라: `data/videos/`의 등록 MP4
- `live` 카메라: 수동 갱신한 ITS CCTV HLS 주소, 브라우저에서 직접 재생
- 관제 화면은 저장된 최대 6개 CCTV를 동시에 재생, 선택하면 지도 오른쪽 상세 패널에 같은 영상을 공유해 표시(추가 연결 없음), 첫 연결 전 상태 문구 표시
- ITS 키는 Backend 환경변수에만 저장, 목록 API는 로그인 없이 `CCTV 주소 갱신` 버튼으로만 수동 호출
- 서버 시작·화면 조회·재생 실패 시 ITS를 호출하지 않음, 갱신 전에는 `data/its-cctv-cache.json`의 저장된 목록만 표시(최초는 비어 있음)
- 영상 연결 오류는 10초 이상 간격으로 최대 3회 자동 재연결, 계속 실패하면 원인(HTTP 상태 등)을 화면에 표시
- 재생 중과 일시적인 버퍼 대기 중에는 영상 위에 연결·재연결 문구를 표시하지 않고, 재생 전 연결 안내와 재생이 멈춘 뒤의 실패 원인만 영상 위에 표시
- HLS 유형 `cctvType=1`의 운영 응답은 HTTP 주소, HTTPS 화면 배포 시 영상 전달 경로 추가 필요
- Backend는 시작 시 저장된 CCTV 6곳을 감시 작업자에 전달, AI 파일이 없으면 대기 상태 표시
- 감시 작업자 종료·프레임 상태 신호 120초 누락 시 Backend가 작업자를 재시작
- Frontend는 30초마다 감시 상태·카메라 정보, 5초마다 탐지 이벤트 조회, 실패 시 마지막 결과와 오류 표시
- 기본 실시간 작업자는 `ai/inference/live_runner.py`, 카메라별 HLS 수신 스레드와 최대 3프레임 대기열을 사용하고 공유 모델로 묶어 추론
- 5fps·16/20 판정을 카메라별 유지, 누락·재접속·큰 장면 변화 시 초기화, 대기열 등록 후 1초 넘은 프레임은 추론 전·후 폐기
- Backend와 AI는 표준 입력의 UTF-8 JSON으로 카메라 이름·좌표를 전달, 디코더 시각 누락·반복 시 마지막 영상 시각과 FPS로 복원하고 실제 양수 시각 역행은 재접속 처리
- 확정 탐지는 위치 없이 먼저 전송, Backend 수락 후 별도 위치 작업자가 같은 실행·클래스의 이벤트에 위치 보완, 위치 계산 지연·실패가 공유 YOLO 추론과 최초 알림을 막지 않음
- 첫 분석 프레임부터 DEM 백그라운드 준비, 준비는 카메라별 1개·위치 대기는 카메라·클래스별 최신 1개로 제한하고 확정 탐지의 위치 작업 우선
- 최초 탐지·위치 보완 모두 로컬 대기열 등록 후 5초 유효시간 적용, 재접속·누락·장면 전환 전의 대기 결과 무효화, 이미 전송 중인 요청 취소는 미지원
- 30초마다 실제 분석 FPS·누적 폐기 수와 배치 추론·프레임 대기·DEM 준비·위치 계산·결과 전달의 횟수·평균·최대 시간(ms)을 Backend 로그에 기록, HLS 서버의 촬영 지연과는 구분
- 실시간 위치 추정은 위경도가 있으면 실행, 이름이 일치하는 고정 자세를 우선 사용하고 없으면 기존 영상 능선·DEM 기반 자동 자세 추정으로 연결
- 화각 설정이 없으면 기본 60°와 경고 사용, 능선 정합 품질 게이트 통과 시에만 좌표 보완, 54°·66° 대체 자세를 오차 범위에 반영
- 위치 준비 실패는 30초부터 최대 300초 간격으로 최신 프레임 재시도, 위치를 준비하지 못해도 탐지·heartbeat·최초 알림 계속 진행
- 큰 장면 변화·해상도 변경·재접속 시 자세와 대기 결과를 무효화하고 약 2초 안정 후 고정 자세 재사용 없이 자동 재추정, 단순 프레임 누락에는 같은 자세를 재사용
- 위치 준비 상태와 실패 사유·기본 화각 경고·재시도 간격은 Backend 로그로 확인, 작은 PTZ 이동·줌 변화의 완전한 감지는 미지원
- 위치 null은 기존 이벤트의 마지막 유효 좌표를 삭제하지 않으며 새 위치 보완 때 갱신
- 실시간 탐지 이벤트는 영상 ID 없이 카메라 ID로 저장, 원본 파일과 결과 프레임은 DB에 저장하지 않음
- 컬럼과 관계는 [ERD](DATABASE.md), 요청·응답은 [API 명세](API_SPEC.md) 참고

## 현재 구현 상태

### 구현

- Backend: 카메라·영상·이벤트 조회, 로컬 영상 스트리밍, 관리자 로그인·JWT, 카메라별 Test 실행·AI 프로세스 실행·MJPEG 중계, 탐지 JSON 검증·저장
- Backend: ITS 6개 CCTV 목록 수동 갱신·캐시, 감시 작업자 시작·상태·재시작, 프레임 상태 신호 수신
- Backend: 이벤트 확인 API(`acknowledged_at` 기록)
- Backend: 카메라별 알림 번호 관리 API, `fire` 탐지 시 SMS 발송과 발송 기록 조회
- Frontend: 지도(확대·닫기, 카메라 좌표, 추정 화점), 지도 아래 ITS HLS 6개 상시 재생, 선택 시 우측 패널 영상 표시, 이벤트 목록, 요약 지표
- Frontend: 위치 표시 등급은 오차 반경 200m 이하 높음·200m 초과~1km 미만 중간·1km 이상 낮음, 실측 정확도 등급과 구분
- Frontend: 1km 미만은 실제 반경 빨간 실선 원(채움 8%), 1km 이상은 반경 500m 주황 점선 참고 원(채움 3%), 원래 오차값을 유지하고 실제 오차 범위가 아닌 참고 표시임을 안내, 반경 미산출은 작은 중심점만 표시
- Frontend: 알림 중인 `fire` 이벤트(확인 전이고 마지막 탐지가 30분 안)가 있는 카메라는 지도 마커를 빨간색으로 표시, 30분이 지나거나 로그인 없이 확인하면 파란색으로 복귀
- Frontend: 새 화재·연기 조회 시 카메라·유형·탐지 시각·신뢰도와 지도 이동·명시적인 확인·나중에 확인을 제공하는 모달 팝업 표시, 닫기·Esc·지도 이동은 확인 상태를 바꾸지 않음
- Frontend: 화재는 빨간색·불꽃 아이콘, 연기는 노란색·연기 아이콘으로 구분하고 동시 수신은 한 팝업에 합침, 같은 CCTV라도 다른 유형은 새 알림으로 처리
- Backend: 화재·연기 팝업 대상은 확인 전이며 마지막 탐지(`ended_at` 우선, 없으면 `updated_at`)가 DB 시각 기준 30분 안인지 `is_popup_alerting`으로 계산, Frontend는 이 값을 사용해 브라우저·DB 시각 차이로 새 연기가 누락되는 문제 방지
- Frontend: 여러 새 탐지를 팝업에 합치고 확인 실패 시 유지, 부분 성공·외부 확인·알림 종료는 대기 목록에 반영, 확인 처리 중 중복 동작 방지
- Frontend: Test 실행·상태·원본 영상·캡처 조회는 로그인 없이 제공, 관리자 로그인은 카메라별 SMS 알림 번호 설정·문자 발송 내역에만 사용
- SMS 제공자는 `console`(기본)과 `solapi`, 가입 본인인증 번호를 발신번호로 쓰는 데모 범위
- 문자는 카메라가 알림 중(확인 전이고 마지막 `fire` 탐지가 30분 안)이 아닐 때 새 `fire` 이벤트가 생길 때만 발송, 작업자·서버 재시작 후에도 중복 발송하지 않음
- 탐지 JSON의 `location_estimation`은 저장하고 지도에 추정 위치로 표시
- AI: Test 실행 시 Backend가 카메라 이름·위경도를 넘기고, 실행 시작 시 카메라 자세를 1회 정한 뒤 탐지마다 추정 위치를 `location_estimation`에 포함

### 미구현 (AI 담당)

- 실시간 6대 동시 분석의 실제 장비 처리 속도·오탐률 검증
- 위치 추정 오차 범위(`error_range_m`), 실행 중 PTZ 자세 변화 감지

### 검증 상태

- 실키 검증: ITS CCTV 6개 HLS 재생목록·영상 조각·CORS 응답, 브라우저 재생 확인
- 솔라피 실발송 1건 확인(SMS 18P, 단말 도착), 운영용 제공자와 별도 발신번호 등록은 미정
- 6개 동시 재생의 부하·끊김은 실제 관제 PC에서 확인 필요
- 영상 서버에 짧은 시간 반복 접속하면 거절될 수 있음(2026-11-03 관찰), 발표 전 새로고침 반복 주의
- 네이버 지도는 콘솔에 등록한 URL로 접속해야 인증 성공

### 개발 환경

- 브라우저 → Vite → Express → PostgreSQL

### 관제 목록 관리

- 대시보드의 `미확인 이벤트 전체 확인`은 필터와 무관하게 서버의 전체 미확인 이벤트를 한 번에 확인, 반환 ID에 해당하는 화면 상태만 즉시 반영
- 탐지 이벤트 행 선택 시 팝업에서 삭제 가능, 확인 후 이벤트·캡처 삭제 및 문자 발송 이력 보존, 분석 중인 이벤트 삭제는 종료 후 허용
- 카메라 목록은 이름·번호·좌표·유형 검색, 더블클릭 또는 Enter로 이름·ID·유형·위경도·등록 시각·제공자 키 상세 팝업 표시
- 카메라 팝업의 별도 링크로 대시보드 카메라 선택 화면에 이동, 알림 전화번호는 공개 카메라 응답에 추가하지 않음

### 테스트 원본·캡처 표시 (#117)

- Test 화면은 등록 원본을 video 요소로 재생, AI의 5fps·16/20 확정 판단과 원본 재생은 독립적
- 새 실행 시작 시 이전 선택 이벤트를 비우고 같은 카메라·영상에서 새로 생성된 이벤트를 상세 패널에 연결
- AI가 확정 탐지 JSON을 수락받은 뒤 최초·영상 시각 기준 최소 5초 간격 캡처를 클래스별로 예약, 별도 작업자가 JPEG 생성·업로드 수행
- 캡처 대기열 최대 2건, 원본 프레임·시각을 함께 보존, 업로드 실패 후 클래스별 실제 5초 대기, 15초 초과 대기 캡처 생략, 영상 종료 시 최대 20초 업로드 정리 대기
- 혼잡·장애 시 캡처 일부가 누락될 수 있지만 캡처 업로드가 다음 프레임 분석을 기다리게 하지 않음
- Backend는 이벤트 행 잠금·트랜잭션으로 캡처 간격을 재검증하고 event_captures에 저장, 탐지 JSON 자체의 이벤트 집계·SMS 정책은 유지
- 팝업은 최신 캡처와 영상 시각 표시, 대시보드 오른쪽은 최신 6장까지 표시하고 `더보기`로 상세 이동, 상세 화면은 캡처 시간순 목록과 이전 기록 추가 조회·원본 해당 시점 이동 제공
- 실시간 HLS 감시와 기존 MJPEG 호환 API는 유지, 현재 Test 화면은 MJPEG 분석 영상에 연결하지 않음
