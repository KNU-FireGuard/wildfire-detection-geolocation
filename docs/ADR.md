## ADR 0001 · JWT 관리자 인증과 공용 SMS 수신자

- 날짜: 2026-10-09
- 상태: 제안
- 배경: 관리자 한 명이 로그인해 산불 알림을 받을 사람을 설정
- 결정
  - `admins`에 로그인 ID와 비밀번호 해시 저장
  - 루트 `.env`의 초기 계정 정보를 Backend 스크립트가 한 번만 INSERT
  - 로그인 API에서 JWT 액세스 토큰 발급
  - `sms_recipients`는 관리자별 목록 대신 시스템 공용 목록
  - SMS 업체 인증 정보는 Backend 설정에서 관리
- 대안: 관리자별 수신자 목록은 현재 운영 방식에 필요하지 않음
- 결과: 비밀번호 원문과 JWT는 DB에 저장하지 않음
- 구현 상태: SQL 테이블과 초기 관리자 생성 스크립트 작성 완료, 로그인·수신자 관리·SMS 발송 미구현
- 남은 결정: JWT 만료·폐기, 전화번호 형식, SMS 발송 규칙, 영상 스트리밍 인증
- DB 스키마 관리: `sql/init.sql`에 포함, 기존 DB에도 누락된 테이블 생성 가능

## ADR 0002 · 녹화 영상의 파일 저장과 스트리밍

- 날짜: 2026-10-09 사후 기록
- 상태: 현행
- 배경: 제공받은 녹화 영상을 관제 화면에서 재생
- 결정
  - 실제 파일은 `data/videos/`에 배치
  - DB에는 파일 경로와 카메라 연결 등 메타데이터만 저장
  - Backend가 `GET /api/videos/:id/stream`과 단일 HTTP Range 요청 제공
- 결과: 큰 파일을 Git·DB에서 분리하고 이벤트를 영상 ID와 연결 가능
- 제약: 파일과 DB 경로를 함께 관리, 파일이 없으면 스트리밍 API `404`
- 기록 한계: 당시 DB 내부 저장·객체 스토리지 비교 자료는 확인되지 않음
- 후속: 실시간 CCTV 입력은 영상 API를 사용할 수 있게 된 뒤 설계

## ADR 0003 · 실시간 입력을 대신하는 4개 영상 데모

- 날짜: 2026-10-09
- 상태: 제안
- 배경: 실시간 CCTV 영상 API를 기다리는 동안 산불 탐지·SMS 흐름을 검증
- 결정
  - Test 버튼 한 번으로 녹화 영상 4개를 처음부터 재생하고 병행 분석
  - 사용자 일시정지·되감기·탐색 기능과 실시간 바운딩박스 표시 제외
  - Backend가 같은 서버의 Python 추론 코드에 영상 경로·카메라 ID 전달
  - AI가 재생 시간에 맞춰 처리하고 `fire`·`smoke` 탐지 JSON을 Backend에 전달
  - Backend가 결과 수신 시각과 연결 영상 ID를 정하고 종류별 SMS 문구 사용
- 대안
  - Frontend가 프레임을 업로드하거나 AI용 FastAPI 서버를 별도 운영
  - 분석 완료 후 박스가 그려진 영상 파일을 재생
- 선택 근거: 현재 서버의 로컬 파일을 바로 읽어 실시간 입력처럼 재생·탐지하는 첫 구현에 필요한 구성으로 제한
- 구현 상태: 조회·영상 스트리밍만 구현, 일괄 실행·AI 추론·이벤트 저장·SMS 발송 미구현
- 제약: DB는 카메라당 여러 영상을 허용하므로 데모 시작 시 영상 4개와 서로 다른 카메라 연결을 검사
- 검증 과제: 4개 영상 병행 추론 속도, 화면·SMS 지연, 이벤트 확정 기준과 SMS 문구·실패 처리
