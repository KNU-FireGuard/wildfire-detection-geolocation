# Frontend 실행·검증

- 실행: `npm.cmd ci`, `npm.cmd run dev`
- 접속: `http://127.0.0.1:5173`
- 단위 테스트: `node --test test/*.test.js`
- 배포 빌드: `npm.cmd run build`
- API 계약: [API_SPEC.md](../docs/API_SPEC.md)

## 구현 범위

- 대시보드 Test 버튼, 4개 영상 영역, 재생 오류·전체/카메라별 분석 상태 표시
- 시작 응답의 영상 URL 사용, 재생 조작·바운딩박스 제외
- 실행 중 약 2초 간격 상태·전체 이벤트 조회, 완료 시 최종 조회
- 이벤트 선택 유지, 화면 이탈 시 요청 취소, 조회 실패 시 기존 결과·재시도 표시
- `/login`: 관리자 로그인, 관리자 이름·로그아웃 표시
- `/sms-recipients`: 로그인 필요, 수신자 추가·수정·활성 상태 변경·삭제
- 토큰은 메모리에만 유지, 새로고침·만료·수신자 API 401 시 로그인 필요
- SMS 발송·탐지 저장·계정 생성은 Backend 담당

## Backend 연동 대기

- develop `6085853` 기준 초기 관리자 생성 스크립트만 추가, 로그인 API는 미구현
- `POST /api/demo-runs`, `GET /api/demo-runs/:id` 구현 필요
- `POST /api/auth/login`, `GET /api/auth/me` 구현 필요
- `/api/sms-recipients` GET·POST·PATCH·DELETE 구현 필요
- 현재 미구현 API 호출은 404 안내, mock 성공으로 대체하지 않음
- Test의 JWT 필요 여부는 미정, 로그인한 경우 토큰 전송
- 실제 탐지 저장과 SMS 발송은 백엔드·AI 연동 후 확인 가능
- 이벤트 API에 실행별 필터가 없어 전체 이벤트로 표시

## 화면 확인 순서

1. API 모드에서 대시보드의 영상 대기 영역 4개와 기존 조회 화면 확인
2. 미구현 상태에서는 Test·로그인 요청의 오류 안내 확인
3. 데모 API 연동 후 Test 1회 클릭, 4개 영상 재생과 개별 분석 상태 확인
4. 실행 중 Test 중복 클릭 방지와 새 이벤트의 목록·지도·상세 반영 확인
5. 영상 파일 오류와 AI 실패가 별도로 표시되는지 확인
6. 상태 조회 실패 시 재시도, 화면 이동 시 조회 중단 확인
7. 로그인 후 수신자 추가·수정·활성 변경·삭제 확인
8. 로그아웃 후 수신자 화면 접근 시 로그인으로 이동하는지 확인
